# 正方 AI 工作台：内嵌原生对话与命令技能设计

版本：v1.0 评审稿；日期：2026-09-06。本文用于后续开发，不代表功能已实现。

## 1. 目标与已确认边界

目标用户为使用工作台完成办公任务、校园问答的用户。当前从工作台发送问题后需要进入另一套页面，历史打开方式也不连贯；首页输入框无法使用 DSH 原生命令和技能选择功能。

本次目标：工作台左侧导航、模式和历史保持稳定；右侧在首页与 DSH 原生对话页之间切换。首页输入框和会话输入框均提供命令、技能入口。

用户已确认：两种输入框都需要支持；Chat 继续保持纯问答边界。Work 可以使用宿主授权的办公、文件、本机和业务能力；Chat 不开放本机、文件修改、执行型技能或业务系统操作。

本次不开发工作空间管理、数据看板、成果空间、智能体广场、AI 工具集；其既定“功能暂未开发”提示保留。现有附件支持不因复用输入框自动承诺扩展，额外格式另按原计划验收。

## 2. 现状与技术证据

核验对象为本机 DSH 0.1.1-rc.2 与 fix/workbench-remediation 分支。

| 现状证据 | 对设计的影响 |
| --- | --- |
| client/workbench-overlay.js 向 Shell 传入 renderEmptySlot、useSessions:null，进入会话回调关闭工作台 | 必须接通原生渲染上下文及会话订阅，不能只取消关闭动作 |
| client/shell.js 已有 conversation 路由，但依赖父级 renderSlot | 对话页可保留现有路由意图，替换空渲染链路 |
| client/root.js 已有 root/conversation/details 布局原型，当前 client.js 未采用该入口 | 可作为开发起点，不能直接视为已兼容实现 |
| DSH runtime 限制 ctx.slots.renderSlot 仅渲染 root，子插槽通过组件 props 渲染 | 禁止通过全局 renderSlot('conversation') 直接拼装 |
| DSH 原生 conversation 注册依赖 layout、sessions、workspaces、输入服务等 | 复用时需保留提供者、会话作用域、详情和审批链路 |
| DSH 输入服务使用 inputTriggers、lexicon、引用序列化和命令判定 | 不用普通文本代替结构化技能引用，不复制一份静态命令清单 |
| DSH 会话对象 command(line) 经 remote.commands.execute 提交命令 | 命令须经原生执行链路，不作为普通模型消息发送 |
| 工作区列表实际为 ctx.workspaces.list 的可订阅快照 | 首页与对话使用同一宿主列表，不建立第二套工作区数据 |

上述为本机源码证据。root 替换的兼容性、原生输入组件可扩展范围、Chat 命令过滤的服务端接入点仍需开发阶段验证；本文不把内部服务名当作稳定公开 API 承诺。

## 3. 方案比较与推荐

| 方案 | 优点 | 代价/风险 | 决策 |
| --- | --- | --- | --- |
| 工作台承载根布局，复用 DSH conversation/details/输入服务 | 保留原生对话、工具卡片、审批、命令和技能行为；单一会话状态 | 需验证根布局注册与其它插件的插槽兼容 | 推荐 |
| 保留官方根布局，仅通过可扩展插槽定制左侧和首页 | 对宿主侵入较小 | 若插槽不足，难以保证所有导航和对话都留在工作台 | 首选方案受阻时的兼容替代，需证明覆盖全部目标 |
| iframe 或自行重写消息流、命令菜单 | 表面上易于嵌入 | 双状态、焦点/弹层问题，审批与插件易失效，维护成本大 | 不采用 |

首选方案只拥有一个可见根布局、一个活动会话输入组件。保留官方插槽声明所有权，避免再次触发 sidebar.settings 重复声明错误。不能把同一输入组件同时挂在隐藏的官方页面和工作台中。

## 4. 页面结构

```text
工作台根布局
├─ 左侧固定导航：品牌 / Work、Chat / 模式菜单 / 搜索与历史 / 用户与设置
└─ 右侧主区域
   ├─ 首页：标题、AI 球、输入框、推荐内容
   └─ 会话页：原生会话标题、消息与工具流、输入/审批区域
      └─ 详情面板：宽屏在右侧展开，窄屏抽屉显示
```

桌面左栏默认沿用 280px，支持折叠；右侧独立滚动。进入会话不重新挂载左栏，保留模式、搜索条件、滚动位置。历史当前项高亮，新增会话在对应模式列表中出现，标题随后跟随宿主更新。

右侧原生对话保留消息流、流式输出、停止生成、重试、复制、工具卡片、批准操作、模型选择、会话轨迹和详情入口；以宿主实际提供且当前模式允许的能力为准。只做容器尺寸与品牌色的轻量适配，不重新实现工具渲染。

新默认入口直接打开工作台。设置仍调用宿主设置界面。兼容期保留“切换到 DSH”入口作为主动操作；正常发送、历史打开及错误恢复不自动跳出工作台。

## 5. 首页、会话与历史交互

### 5.1 首页发送

用户填写正文、选工作区/模型/技能 → 校验 → 获得正确模式的会话 → 等待输入服务就绪 → 转交正文、附件及引用 → 原生发送 → 右侧展示该会话。左栏不变。

发送全过程只保留一条提交链路。双击发送不能重复建会话或重复提交。仅在宿主确认接收后清空原草稿；失败保留正文、附件、引用和选择。若会话已建立而发送失败，在该会话显示重试，复用其 ID。

会话页继续发送、取消、审批均走原生输入/对话服务。旧的工作台 HTTP startSession 路径与原生发送不得同时执行相同消息。

### 5.2 历史打开

点击历史 → 记录目标 sessionId → 打开并订阅宿主会话 → 右侧显示加载态 → 原生消息展示。标题、运行状态与后续回复继续同步。

快速连续点击时最后一次选择生效；前一次异步完成不能覆盖后一次。会话被删除或不可访问时，右侧显示原因和“重试”“返回首页”，保留左栏。自动化运行记录中的“查看对话”走同一入口。

### 5.3 切换与恢复

Work、Chat 首页草稿分别保存；会话草稿按 sessionId 隔离。切换模式不停止后台任务，不迁移工具权限，不把正文或附件复制到另一模式。

刷新恢复最后访问的 mode、route、sessionId；恢复前检查会话是否存在及其模式。旧会话依照已有迁移规则归入 Work，不因浏览历史更改其权限。初次访问使用既有默认模式设置。

## 6. 原生命令设计

两处输入框提供“命令”按钮及 `/` 触发。菜单位置、选中样式、滚动和键盘交互尽量复用 DSH 原生实现。输入过滤文字时动态检索当前模式允许的宿主命令。

菜单支持上下键移动、Enter 选择、Esc 关闭；中文输入法组词中的 Enter 不提交。选择需要参数的命令后保留参数编辑，选择具有原生弹窗的命令则打开该弹窗。未知命令显示明确提示，不静默当普通问题发送。

| 命令类别 | 首页行为 | 会话页行为 |
| --- | --- | --- |
| 模型选择 | 设置本次会话模型；若宿主必须有会话则先建立准备会话 | 修改当前会话模型 |
| 压缩、导出等依赖历史的操作 | 可搜索看到，但标记“开始对话后可用”，不创建无意义会话 | 按宿主规则执行；无可处理历史时说明原因 |
| Work 的权限、计划、目标等 | 明确选择执行后按需建 Work 会话，再执行 | 使用宿主原生命令与批准机制 |
| 当前模式不允许或宿主未提供 | 不作为可执行菜单项 | 同样不允许，粘贴命令也受校验 |

附件中 compact、export、feedback、goal、permission、plan、model 仅为参考实例。最终菜单从运行时目录生成，描述可本地化但不改变命令标识及参数语法。

## 7. 技能选择与真实调用

两处输入框均提供“技能”入口，支持按名称、描述搜索。列表展示名称、来源、简介、可用状态；同名技能必须通过来源或相对标识区分。使用 DSH 实际注册的技能目录与引用机制；快捷触发符沿用宿主核验结果，不预先硬编码为 @ 或 $。

选中技能表示将真实技能引用绑定到待发送内容，默认不立即执行。选中后显示可移除引用，保留已有正文。提交时按原生引用序列化规则处理，由宿主解析并执行；不得仅把任意 skill ID 写进提示词就宣称完成对接。

输入框的显式技能引用与能力库“默认偏好”区分：前者属于本次消息，后者只影响推荐，均不扩大宿主权限。技能实际调用与结果在右侧原生工具流可查看；“已选择”“调用中”“调用失败”不能混为“已完成”。

不可用、缺少依赖、停用的技能不能插入执行引用，并显示原因。编辑草稿后技能被移除或停用时，发送前重新校验，允许用户移除失效引用后再提交，不静默忽略。

## 8. Chat 边界与命令策略

Chat 保留入口一致性，但列表只展示可用且符合问答边界的能力。当前受限 Chat 预设不含技能执行服务时，技能菜单显示空态：“当前聊天模式没有可用技能”，附“切换到 Work”操作。切换由用户主动发起；不自动携带附件或执行请求。

| 能力 | Work | Chat |
| --- | --- | --- |
| 模型选择、适用的会话压缩/导出 | 按宿主支持 | 经分类审核后允许 |
| 反馈提交 | 宿主原生交互 | 可保留明确提交确认，不后台自动发送 |
| 权限提升、本机命令、文件操作、业务系统操作 | 按宿主授权 | 禁止 |
| 计划/目标等执行导向命令 | 按宿主支持 | 本期不开放 |
| 技能 | 真实注册且可用的技能 | 本期默认无；未来仅显式审核的问答技能 |

限制必须同时覆盖菜单、粘贴命令、原生输入判定和宿主执行入口。未知命令或新增插件在 Chat 默认不放行。不得仅靠隐藏按钮、提示词或用户承诺维持边界；不能借 /permission 或更换预设升级为 Work。

## 9. 会话建立与数据归属

首页浏览命令不发送消息。若原生目录/输入组件需要会话作用域，可为当前 mode 懒建立“准备会话”，仅在首次打开命令/技能入口或提交时创建，同一草稿复用一次。准备会话绑定正确预设与工作区，不自动调用模型。

准备会话不进入工作台普通历史，首次有效消息被接收或命令产生有效记录后转为普通会话。离开首页不自动删除宿主会话；清理由已有宿主生命周期处理。若宿主无法避免准备会话污染原生历史，兼容验证阶段需选择可复用空会话方案并记录结果。

| 数据 | 建议字段 | 权威来源 |
| --- | --- | --- |
| 导航 | mode、route、activeSessionId、lastVisitedAt | 工作台；活动会话与宿主协调 |
| 首页草稿 | text、attachments、references、workspaceId、modelSelection、draftRevision | 工作台持久化，提交交接后原生输入服务接管 |
| 会话草稿 | 按 sessionId 的原生草稿 | DSH 输入服务 |
| 会话归类 | sessionId、mode、origin、lifecycle(prepared/active)、createdAt | 工作台元数据，与宿主 ID 绑定 |
| 命令项 | id、label、description、requiresSession、availability | 宿主目录加工作台模式策略 |
| 技能引用 | source、referenceId、displayName、version（若宿主提供） | 宿主引用格式；不得自行假造执行 ID |
| 加载/发送状态 | idle/loading/ready/error、operationId、errorCode | 适配层，不持久化为已执行事实 |

表中为建议内部字段，不是已存在的 DSH API。旧元数据新增字段采用可选兼容读取；不得改写历史消息正文或删除已有会话。

## 10. 开发模块与接口职责

1. RootShellAdapter：核验和承载原生子插槽、layout 面板、设置与 overlay，确保插槽唯一声明。
2. SessionNavigationAdapter：协调 mode/sessionId、原生打开事件、加载竞态、历史刷新与错误返回。
3. HomeComposerBridge：保持首页外观，复用原生输入机制；处理准备会话、草稿交接、附件/引用保真与重复提交。
4. ModeCommandPolicy：从目录与已审核分类产生菜单和执行准入；Chat 服务端限制必须覆盖原生提交路径。
5. CapabilityReferenceAdapter：加载当前会话实际可用技能、选择/移除、校验与序列化。

以上为拟开发模块名。优先复用现有 root.js、shell.js、store.js、sidebar.js、work-home.js、chat-home.js；新增适配层只处理宿主差异，不复制命令执行器和消息状态机。

## 11. 异常、键盘和布局

- 会话载入失败：右侧可重试，左栏始终可用；草稿不丢失。
- DSH 断线：显示连接状态，阻止重复提交；恢复后重新订阅，不重发已接收消息。
- 命令目录失败：菜单显示“加载失败 / 重试”，普通消息可用性单独判断。
- 运行中切换会话：后台继续执行，历史提供运行状态，不重复订阅或启动。
- 审批弹层、设置、菜单和详情统一挂载在当前壳层内，不能被遮挡、裁切或落到隐藏页面。
- Enter 沿用已确认发送习惯；Ctrl+Enter 换行；候选菜单打开时 Enter 优先选择，输入法组合优先。
- 1280/1440/1920 宽屏分别验收；1024 以下折叠左栏、详情改抽屉。菜单不超出视口。
- 焦点：打开历史聚焦对话主区/输入；关闭菜单回输入框；关闭详情回触发工具行。

## 12. 分阶段交付与验收

阶段一为宿主兼容验证：证明根布局能正确渲染 conversation/details、输入菜单、审批及设置，无重复声明或双输入实例。失败则核验方案二；不能以全屏覆盖官方页替代验收。

阶段二接通会话导航：发送和历史均在工作台内展示、刷新恢复、竞态和草稿交接通过。

阶段三接通两类输入框的命令与技能：原生目录、真实引用、单一发送链路、Chat 两层约束通过。

阶段四集成验收与回滚：桌面适配、其它插件共存、断线恢复、现有测试回归、数据兼容和原版本恢复。

| 编号 | 操作 | 通过标准与证据 |
| --- | --- | --- |
| N01 | Work 首页发送一个问题 | 左栏持续存在，右侧显示用户消息和流式回复；截图与会话 ID |
| N02 | Chat 首页发送并续问 | 全过程在工作台内且受限预设不变；会话与工具目录证据 |
| N03 | 点击两条历史并快速切换 | 最后目标生效，消息不串线，当前项高亮；操作录像/状态记录 |
| N04 | 刷新会话页 | 恢复对应模式和会话，无重复消息或新建会话 |
| N05 | 首页与会话页输入 / | 均显示真实动态目录，过滤/键盘/IME 正常 |
| N06 | 执行 model、compact、export | 模型生效、压缩/导出走宿主逻辑；首页无历史操作被正确禁用 |
| N07 | 首页和续问各选择并调用一个技能 | 原生轨迹包含真实技能调用及结果，不只出现名称 |
| N08 | Chat 粘贴越权命令、引用执行技能 | UI 和宿主执行均拒绝，无本机或业务工具执行 |
| N09 | Work 触发需审批操作 | 审批可见可交互，未批准不执行；使用受控测试环境 |
| N10 | 双击发送、模拟断线和发送失败 | 一条消息/会话，正文及附件引用可恢复 |
| N11 | 打开工具详情、设置、模型菜单 | 无遮挡、重复弹层、焦点逃逸，左栏保持 |
| N12 | 插件停用或目录变化后发送引用 | 重新校验并明确提示，不冒充执行成功 |
| N13 | 从自动化运行记录打开会话 | 同一工作台右侧展示正确运行会话 |
| N14 | 宽度适配与返回 DSH | 布局可用；仅主动切换才离开工作台 |
| N15 | 回滚到改造前构建 | 历史、草稿可读取，无强制数据迁移或丢失 |

单元测试聚焦导航竞态、草稿交接、幂等提交和策略边界；真实宿主验收必须覆盖插槽、原生菜单、技能执行和审批，不能以源码字符串测试替代。

## 13. 兼容与发布条件

继续在隔离分支开发并记录起点提交，先在当前 RC2 宿主完成兼容验证。切换根布局通过可回退配置启用；具体配置键在开发方案中确定。打包前校验依赖与最低支持版本，升级 DSH 时重跑原生接口验收。

仍需开发验证的技术问题：根布局替换是否与现有品牌/侧栏插件共存；首页原生输入复用能否保留设计布局；Chat 原生命令执行的服务端拦截方式；准备会话生命周期。它们不改变用户已确认目标，也不能被默认为已解决。

若其中任一技术条件不成立，应提供可复现证据及替代方案。涉及改变用户操作（例如移除首页命令能力）时再向用户确认，不自行缩减范围。
