# 正方 AI 工作台（DSH Web 二次改造）详细设计文档

- 文档状态：已由用户确认，作为实施基线
- 文档日期：2026-09-04
- 目标分支：`feature/work-chat-redesign`
- 当前仓库：`dsh-skills-manager`
- 设计阶段：功能与技术方案，不包含实现代码
- 首期形态：本地、单用户、随 `dsh web` 进程运行的独立插件

## 1. 文档目的

本文档定义“正方 AI 工作台”首期版本的产品范围、页面结构、核心流程、权限边界、数据模型、技术接入方式、异常处理和验收标准，为后续拆分开发计划、编码、联调与验收提供唯一基线。

本项目不是对现有 `dsh-skills-manager` 的界面换皮，也不 Fork DSH 核心代码。项目将在当前代码仓库中新增独立的 AI Workbench 插件包；现有技能管理器继续作为独立插件存在，并承担高级技能管理能力。

## 2. 背景与问题

当前 DSH Web 更接近通用 Agent 工作界面，缺少面向校园办公场景的明确入口和模式约束：

1. 办公执行与普通问答混在同一入口，用户难以判断 AI 当前具备哪些权限。
2. 技能、工具和业务系统能力分散，普通用户缺少易理解的能力目录。
3. 现有 DSH 会话内定时提醒不足以承担可管理、可追踪的全局自动化任务。
4. 设计稿中的 Work、Chat 首页和校园快捷内容尚未形成可开发的完整交互定义。
5. DSH 仍处于预发布阶段，直接复制或修改核心 UI 会带来较高升级维护成本。

## 3. 产品目标

### 3.1 核心目标

1. 将产品明确拆分为 Work 与 Chat 两种模式。
2. Work 面向日常办公执行，可操作授权目录、调用本机工具、Skills 和业务系统。
3. Chat 面向问答咨询，仅允许模型问答、附件只读、深度思考和联网搜索。
4. 提供面向普通用户的能力库，并可跳转到现有技能管理器进行高级管理。
5. 提供类似 Codex“已安排任务”的本地自动化任务能力。
6. 最大程度复用 DSH 官方会话、消息、附件、审批和设置能力。
7. 新插件可独立禁用或卸载，恢复原版 DSH Web，不破坏原会话数据。

### 3.2 成功标准

1. 用户能在 10 秒内理解 Work 与 Chat 的区别。
2. 两种模式的 Agent、能力、权限、草稿和历史记录严格隔离。
3. 设计稿中的首期可用入口均具备完整交互，不可用入口均提供统一说明。
4. 自动化任务可创建、暂停、恢复、执行、等待审批并查询每次运行记录。
5. 插件禁用后，官方 DSH 界面和原始会话仍可正常访问。

## 4. 目标用户与核心场景

### 4.1 目标用户

首期面向在本机使用 DSH Web 的高校教职工或行政人员。用户不需要理解 Agent、MCP、Cron 或技能来源等技术概念。

### 4.2 Work 核心场景

1. 汇总课表和考勤，分析教学情况并生成周报。
2. 核对科研、人事或就业数据并生成简报。
3. 汇总通知、会议记录，提取待办并起草纪要。
4. 调用本机文件、校园业务系统或已安装 Skill 完成办公任务。
5. 将重复任务配置为自动化，在计划时间运行并保留执行记录。

### 4.3 Chat 核心场景

1. 询问校园制度、办事流程和联系方式。
2. 上传文件并进行只读总结、解释或问答。
3. 开启深度思考处理复杂问题。
4. 开启联网搜索获取外部公开信息。
5. 通过“猜你喜欢”“热门办理”和服务导航快速发起问题或打开校园页面。

## 5. 产品范围

### 5.1 首期必须实现

1. 新的品牌壳层与侧边栏。
2. Work / Chat 模式切换。
3. Work 首页、任务输入与推荐场景。
4. Chat 首页、问答输入与快捷内容。
5. Work 和 Chat 独立历史列表。
6. Work 能力库简化页面。
7. 自动化任务列表、创建、编辑、暂停、恢复、删除和运行详情。
8. 语音转文字、附件选择和发送前确认。
9. Work 智能执行配置和本次任务能力选择。
10. 未开发功能统一提示弹窗。
11. 现有 DSH 会话迁移为 Work 历史记录。
12. 1024px 及以上桌面响应式适配。
13. 插件禁用后的安全回退机制。

### 5.2 首期明确不实现

1. “工作空间”管理页面。
2. “数据看板”页面。
3. 跨任务聚合的“成果空间”。
4. Chat“智能体广场”。
5. Chat“AI 工具集”。
6. 多用户登录、组织、角色和租户权限。
7. 云端调度、远程唤醒和电脑关机后的执行。
8. 面向手机的专项布局。
9. 深色主题和主题切换。
10. 向普通用户直接暴露 Cron 表达式。

## 6. 已确认的关键产品决策

| 主题 | 结论 |
| --- | --- |
| 产品形态 | 新建独立“正方 AI 工作台”插件；现有技能管理器保持独立 |
| 技术接入 | 新插件接管 DSH Web Root 和 Sidebar，复用官方内部能力 |
| Work / Chat | 不同 Agent、权限策略、草稿与历史列表，强隔离 |
| Work 能力 | 工作空间、文件、本机工具、Skills、已连接业务系统 |
| Chat 能力 | 模型问答、附件只读、深度思考、联网搜索 |
| 能力库 | 普通用户简化目录；高级管理跳转现有技能管理器 |
| 自动化范围 | 支持提醒和 Work 自动化；高风险动作进入等待批准 |
| 推荐场景 | 任务模板，预填任务并预选能力，不直接执行 |
| Chat 快捷内容 | 猜你想问/热门办理预填输入框；服务导航打开配置链接 |
| 自动选择 | 自动选择模型、能力和执行强度，允许用户展开覆盖 |
| 语音 | 仅语音转文字，用户确认后发送 |
| 工作空间 | 菜单页暂不开发；Work 输入区现有工作空间选择器保留可用 |
| 主题 | 首期仅浅色，按现有设计稿验收 |
| 响应式 | 桌面优先；小于桌面宽度时侧栏折叠、卡片单列 |
| 会话迁移 | 现有 DSH 会话全部归入 Work，并标记“历史导入” |
| 自动化运行 | 浏览器可关闭；`dsh web` 进程必须运行；休眠/停机时不执行 |
| 漏跑补偿 | 一次性任务恢复后补跑一次；周期任务只补最近一期 |

## 7. 信息架构

### 7.1 全局壳层

页面由固定左侧栏、主内容区和复用的详情面板构成。

左侧栏从上到下包括：

1. 品牌区：蓝色品牌图形 + 实时渲染文字“正方 AI 工作台”。
2. Work / Chat 分段切换器。
3. 当前模式的功能导航。
4. 当前模式的历史记录列表与搜索。
5. 底部本地用户展示与设置入口。

模式切换仅改变导航、首页、能力与历史列表；已有会话不会被转换为另一种模式。

### 7.2 Work 导航

| 导航项 | 首期状态 | 点击行为 |
| --- | --- | --- |
| 新建任务 | 可用 | 打开 Work 首页并创建/恢复空白草稿 |
| 工作空间 | 占位 | 弹窗提示“功能暂未开发” |
| 能力库 | 可用 | 打开能力目录页 |
| 数据看板 | 占位 | 弹窗提示“功能暂未开发” |
| 自动化任务 | 可用 | 打开自动化列表页 |
| 成果空间 | 占位 | 弹窗提示“功能暂未开发” |

侧栏下半部分显示 Work 任务历史，按日期分组，支持标题搜索。自动化每次运行生成的 Work 记录也显示在这里，并带自动化来源标记。

### 7.3 Chat 导航

| 导航项 | 首期状态 | 点击行为 |
| --- | --- | --- |
| 新建对话 | 可用 | 打开 Chat 首页并创建/恢复空白草稿 |
| 智能体广场 | 占位 | 弹窗提示“功能暂未开发” |
| AI 工具集 | 占位 | 弹窗提示“功能暂未开发” |

侧栏下半部分显示 Chat 对话历史，按日期分组并支持搜索。Chat 历史中不得出现 Work 任务或自动化运行记录。

## 8. 视觉与响应式规范

### 8.1 视觉基线

1. 以用户提供的 Work、Chat 两张设计稿作为首期视觉基线。
2. 使用用户提供的蓝色品牌图形，品牌文字必须用 HTML 文本实时渲染，避免原始整图文字裁切问题。
3. 首页 AI 球使用用户提供的 `02_AI球_完整.png`，不得用 CSS 图形或近似图标代替。
4. 首期只实现浅色主题：白色主背景、浅灰蓝辅助背景、蓝色主操作色。
5. 普通功能图标优先使用项目统一图标库；已有切图只在与设计稿完全一致且尺寸合适时使用。
6. 不新增设计稿中不存在的渐变卡片、装饰插画或营销模块。

### 8.2 原始设计与品牌资产

开发时需从以下原始文件导入并纳入插件资源目录：

- `/Users/yekechao/Downloads/AI工作台完整前端切片/01_logo_完整.png`
- `/Users/yekechao/Downloads/AI工作台完整前端切片/02_AI球_完整.png`
- 同目录下 `03_icon_新建任务.png` 至 `17_scene_工作量分析.png`

其中 `01_logo_完整.png` 只作为品牌图形取样来源，不直接整图展示；最终品牌区采用蓝色图形资源 + 文本“正方 AI 工作台”。

### 8.3 响应式规则

1. 主要验收宽度：1440px 及设计稿原始比例。
2. 最低支持宽度：1024px。
3. 宽度不足时，侧栏自动折叠为图标栏，并提供显式展开按钮。
4. Work 推荐场景和 Chat 内容卡片由多列变为单列。
5. 主输入区保持可读宽度，不允许被详情面板挤压到不可编辑。
6. 首期不保证手机端完整操作，但不能出现横向内容永久不可达。

### 8.4 可访问性

1. 所有图标按钮必须有可访问名称和 Tooltip。
2. Work / Chat 切换、菜单、能力开关和状态筛选支持键盘操作。
3. 焦点样式必须清晰，颜色对比符合 WCAG AA 的常规文本要求。
4. 状态不能只用颜色表达，必须同时显示文字或图标标签。
5. 动效遵循系统“减少动态效果”设置。

## 9. Work 模式详细设计

### 9.1 首页结构

1. AI 球与标题“今天，想完成什么工作？”
2. 大尺寸任务输入框。
3. 输入框左侧：添加附件、请求批准状态入口。
4. 输入框右侧：智能执行配置、语音转文字、发送按钮。
5. 输入框下方：工作空间选择、附件摘要、能力选择器。
6. 下方推荐场景区域，桌面端两列，窄屏单列。

### 9.2 新建任务流程

1. 用户进入 Work 首页。
2. 输入任务描述，或点击推荐场景预填模板。
3. 可选择工作空间和附件。
4. 系统根据任务自动建议模型、能力和执行强度。
5. 用户可展开“自动选择”查看并覆盖建议。
6. 用户检查任务描述、工作空间、文件和能力后发送。
7. 系统创建 Work 会话并进入官方 DSH Conversation 视图。
8. 执行过程中按统一权限策略自动运行或请求批准。

### 9.3 推荐场景

推荐场景由配置驱动。每项至少包含：

- `id`
- `title`
- `promptTemplate`
- `recommendedCapabilityIds`
- `sortOrder`
- `enabled`

点击场景后只更新当前 Work 草稿，预填任务模板并预选推荐能力，不创建会话、不自动发送、不自动访问文件。

### 9.4 工作空间选择器

左侧导航中的“工作空间”管理页首期不开发，但 Work 输入区必须继续复用 DSH 已有工作空间选择能力。用户可在发送前选择当前任务所在目录；工作空间路径将参与文件权限和高风险动作判断。

### 9.5 能力选择器

能力选择器按三组展示：

1. Skill：本地 Agent Skills。
2. DSH 工具：文件、终端、网页、子任务等宿主工具。
3. 业务系统：已连接的校园系统或插件提供能力。

能力库中的启用状态是全局默认；输入区选择器是本次任务配置。本次选择可以减少或增加当前任务建议能力，但不能绕过宿主权限策略。

### 9.6 智能执行配置

“自动选择”由三部分构成：

1. 模型选择。
2. 能力组合。
3. 执行强度或推理强度。

默认折叠展示摘要。用户展开后可以逐项覆盖；一旦覆盖，显示“已自定义”，并提供“恢复自动选择”。首期不承诺自动选择算法智能化，可先采用规则和能力声明实现，但 UI 与数据结构需为后续策略升级预留。

### 9.7 语音输入

1. 点击麦克风后请求浏览器麦克风权限。
2. 录音结果只转为文本并写回输入框。
3. 转写失败时保留原草稿并显示可重试错误。
4. 转写完成后不自动发送。
5. 未授权时说明如何开启权限，不循环弹窗。

## 10. Chat 模式详细设计

### 10.1 首页结构

1. AI 球与标题“有什么校园问题想问我？”
2. 问题输入框。
3. 输入框左侧：附件、深度思考、联网搜索。
4. 输入框右侧：语音转文字、发送按钮。
5. 下方三类内容：猜你喜欢、热门办理、服务导航/文档资料。

### 10.2 Chat 能力白名单

Chat 只允许：

1. 模型问答。
2. 用户显式添加附件的只读访问。
3. 深度思考。
4. 联网搜索。

Chat 禁止：

1. 本机目录扫描和任意文件写入。
2. 终端、桌面控制或系统操作。
3. Work Skills 和业务系统执行工具。
4. 对外发送消息、提交表单和产生业务副作用。

白名单必须在宿主 Agent/工具注入层执行，不能仅通过隐藏前端按钮实现。

### 10.3 快捷内容

“猜你喜欢”和“热门办理”由本地配置驱动。点击项目后把对应问题写入 Chat 输入框，用户可继续编辑后发送。

“换一批”只改变当前展示集合，不产生请求。配置不足一批时展示全部，不重复填充。

### 10.4 服务导航与文档资料

每个入口至少包含：

- `id`
- `title`
- `category`
- `url`
- `icon`
- `sortOrder`
- `enabled`

点击后打开配置 URL。没有配置时展示明确空状态和“请联系管理员配置”，不得填入虚构校园地址。

### 10.5 草稿与历史

Work 和 Chat 各自保存一个未发送草稿。切换模式时保存当前草稿并恢复目标模式草稿。Chat 会话创建后写入 Chat 模式元数据，只出现在 Chat 历史中。

## 11. 会话模式与旧数据迁移

### 11.1 模式元数据

DSH 原会话数据不改写。新插件为会话维护附加元数据：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `sessionId` | string | DSH 会话 ID |
| `mode` | `work` \| `chat` | 所属模式 |
| `origin` | `user` \| `automation` \| `migration` | 创建来源 |
| `automationId` | string? | 自动化来源 ID |
| `runId` | string? | 自动化运行 ID |
| `importedAt` | string? | 旧会话迁移时间 |

### 11.2 迁移规则

1. 首次启用插件时扫描尚无模式元数据的现有 DSH 会话。
2. 所有现有会话写入 `mode=work`、`origin=migration`。
3. UI 显示“历史导入”标签。
4. 迁移只写附加元数据，不修改消息、附件、标题、工作空间或原始时间。
5. 迁移过程可重复执行，已有元数据的会话不覆盖。
6. 迁移失败时停止后续批次并提示，不删除已经成功写入的元数据。
7. 禁用插件后，DSH 官方 UI 仍按原方式显示全部会话。

## 12. 能力库详细设计

### 12.1 页面目标

能力库用于回答三个问题：当前有哪些能力、它们来自哪里、是否默认启用。它不复制现有技能管理器中的创建、导入、删除、恢复和来源诊断功能。

### 12.2 页面结构

1. 标题和说明。
2. 能力总数、已启用数、已停用数。
3. 名称/描述搜索。
4. 来源、分类、状态筛选。
5. 能力列表或分组卡片。
6. 单项启停、查看详情。
7. “高级管理”按钮。

### 12.3 能力统一模型

| 字段 | 说明 |
| --- | --- |
| `id` | 稳定能力标识 |
| `name` | 展示名称 |
| `description` | 简短说明 |
| `kind` | `skill`、`dsh-tool`、`business-system` |
| `source` | 提供该能力的插件或系统 |
| `category` | 业务分类 |
| `enabled` | 全局默认启用状态 |
| `availability` | `available`、`unavailable`、`misconfigured` |
| `riskLevel` | `low`、`medium`、`high` |
| `detailTarget` | 详情页或高级管理定位信息 |

### 12.4 高级管理

点击“高级管理”打开现有 `dsh-skills-manager` 完整技能管理界面。若技能管理器未安装或不可用，显示安装/启用说明，不在新插件中静默降级为伪造页面。

## 13. 自动化任务详细设计

### 13.1 自动化类型

1. 提醒：在指定时间创建提醒记录并发送本地通知，不调用高权限能力。
2. Work 自动化：按保存的 Work 模板、工作空间和能力配置创建独立运行会话。

### 13.2 自动化列表

页面结构参考 Codex“已安排的任务”：

1. 页面标题和用途说明。
2. 搜索框。
3. 状态筛选：全部、已开启、已暂停、已完成。
4. 自动化列表：名称、摘要、计划、下次运行、最近结果、状态。
5. 创建自动化按钮。
6. 空状态与建议模板。

### 13.3 创建与编辑字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `name` | 是 | 自动化名称 |
| `type` | 是 | `reminder` 或 `work` |
| `prompt` | 是 | 提醒内容或 Work 任务描述 |
| `schedule` | 是 | 结构化调度规则 |
| `timezone` | 是 | 默认本机时区 |
| `workspaceId/path` | Work 必填 | 运行工作空间 |
| `capabilityIds` | 否 | 固定或自动选择的能力 |
| `executionProfile` | 否 | 模型与执行强度配置 |
| `notificationPolicy` | 是 | 完成、失败、等待批准通知 |
| `enabled` | 是 | 是否启用 |

### 13.4 调度规则

普通用户可选择：

1. 仅一次。
2. 每日。
3. 每周。
4. 每月。
5. 工作日。
6. 指定星期。
7. 每 N 分钟、小时或天。

UI 使用结构化表单，不显示 Cron。内部数据使用可验证的结构化 schedule 对象，并计算 `nextRunAt`。时区默认使用本机时区，用户修改系统时区后重新计算后续触发时间。

### 13.5 运行状态

自动化定义状态：

- `active`
- `paused`
- `completed`（一次性任务完成）
- `disabled_by_error`

单次运行状态：

- `scheduled`
- `running`
- `waiting_approval`
- `succeeded`
- `failed`
- `rejected`
- `skipped`
- `cancelled`

### 13.6 运行流程

1. 宿主调度器到达计划时间。
2. 使用 `automationId + plannedAt` 生成幂等键。
3. 若已有同幂等键运行记录，则跳过重复触发。
4. 若同一自动化已有 `running` 或 `waiting_approval` 运行，本次记为 `skipped`，原因是前次未结束。
5. 创建独立 Work 会话，并关联 `automationId` 和 `runId`。
6. 按保存的工作空间、能力和执行配置开始任务。
7. 遇到高风险动作时转为 `waiting_approval`，暂停当前执行。
8. 用户批准后从暂停点继续；拒绝后记录 `rejected`，不执行该动作。
9. 完成、失败或等待批准时触发本地通知。
10. 详情页可跳转到完整 Work 会话查看过程。

### 13.7 浏览器关闭、休眠和补跑

1. 调度器运行在 `dsh web` 宿主进程，不依赖浏览器页面保持打开。
2. 浏览器关闭但宿主进程运行时，自动化继续触发。
3. 电脑休眠、关机或宿主进程停止时不执行。
4. 宿主恢复后，一次性任务如已过期且从未执行，补跑一次。
5. 周期任务只补最近一个漏跑周期，不追跑全部历史周期。
6. 补跑仍遵循幂等、不重叠和审批规则。

### 13.8 通知

首期通知事件：

1. 执行成功。
2. 执行失败。
3. 等待用户批准。

优先使用本地系统通知适配器。系统通知不可用或授权被拒绝时，将事件保存到应用内通知列表，用户下次打开页面后可见。通知只包含摘要，不展示附件内容、敏感数据或完整任务文本。

## 14. 权限与安全设计

### 14.1 原则

1. 权限由宿主执行层强制，不以 UI 可见性作为安全边界。
2. Work 采用“授权范围内自动、越界或高风险审批”的策略。
3. Chat 采用能力白名单，默认拒绝所有未声明能力。
4. 自动化继承 Work 权限，但无人值守时不得自动越过审批。

### 14.2 Work 风险划分

低风险、可在授权范围内自动执行的典型动作：

- 读取用户已选择的文件。
- 在已授权工作空间内进行分析。
- 生成草稿或预览。
- 调用无副作用的信息查询能力。

必须请求批准的典型动作：

- 写入授权工作空间之外的位置。
- 删除、覆盖或批量重命名文件。
- 对外发送消息、邮件或通知。
- 提交表单、审批、发布或执行不可逆业务动作。
- 权限声明为高风险的业务系统调用。

审批卡必须展示：动作名称、目标对象、影响范围、关键参数和批准/拒绝按钮。敏感值按 DSH 现有规则脱敏。

### 14.3 自动化审批

自动化遇到审批后必须暂停，不得自动假设批准。等待期间不重复执行相同高风险动作；后续周期因前次未结束而记为跳过。用户拒绝后结束当前动作并记录结果。

## 15. 技术架构

### 15.1 接入方案

采用“替换应用壳层，复用内部能力”：

1. 新插件注册 DSH Web `root` 和 `sidebar` 插槽占用者。
2. 自定义 Root 重新声明官方壳层所需的 `sidebar`、`conversation`、`details`、`shell.overlay` 等子插槽。
3. Work/Chat 首页、能力库、自动化页由新插件渲染。
4. 已创建会话继续使用官方 Conversation、Details、Settings、附件和审批组件。
5. 新插件负责页面路由、模式状态、导航和页面级服务。

不选择浮层方案，因为焦点、滚动、响应式和层级长期不稳定；不复制官方 Conversation，因为会产生高昂同步成本。

### 15.2 代码组织

当前仓库保留现有技能管理器根包，并新增独立 AI Workbench 包。建议结构在实现计划阶段最终落位：

```text
dsh-skills-manager/
├── src/、assets/、scripts/、test/       # 现有技能管理器，保持兼容
├── packages/
│   └── ai-workbench/                   # 新独立插件
│       ├── src/client/                 # Root、Sidebar、页面与组件
│       ├── src/host/                   # 调度、聚合、迁移与通知
│       ├── assets/                     # 品牌、AI 球、场景图片
│       ├── test/                       # 单元、契约与集成测试
│       └── package.json
└── docs/superpowers/specs/
```

是否将仓库升级为 npm/pnpm workspace，由实现计划根据现有构建脚本影响评估决定；不得为引入新包而破坏现有发布流程。

### 15.3 复用边界

必须优先复用：

- DSH Client Runtime。
- DSH UI Slots。
- 官方 Conversation、Details、Settings。
- DSH Session 与会话查询。
- DSH Attachment。
- DSH Agent Presets 与 Permission Presets。
- DSH Skill / Tools 注册信息。
- DSH Storage Hub 与 JSON KV 后端。
- DSH Host API Proxy / Webserver。

新插件自行实现：

- 品牌壳层和 Work/Chat 导航。
- 页面路由和双模式草稿。
- 会话模式附加元数据。
- 能力目录聚合与默认开关。
- 首页内容配置。
- 持久化自动化调度器。
- 自动化定义、运行记录、补跑和幂等。
- 本地通知适配与应用内降级。

### 15.4 持久化

首期使用 DSH Storage Hub 的 JSON KV 后端保存非会话领域数据。原因：首期是单宿主进程、单用户、数据规模有限，JSON KV 已具备原子替换和持久写入语义，无需增加数据库依赖。

建议建立一个稳定 KV unit，保持后端 unit 版本不频繁变化，在业务记录中维护应用级 `schemaVersion` 和显式迁移逻辑。建议表：

- `session_modes`
- `capability_preferences`
- `automations`
- `automation_runs`
- `home_content`
- `notifications`
- `drafts`

写入必须串行化。若未来运行记录量明显增长，再评估 SQLite；首期不提前引入。

## 17. 页面状态、异常与边界

### 17.1 通用状态

所有可用页面必须设计：加载、空数据、正常、部分失败、完全失败五类状态。错误信息需说明发生了什么、是否影响数据、用户下一步能做什么。

### 17.2 未开发页面弹窗

标题：`功能暂未开发`

正文：`该功能尚未在当前版本开放，后续版本将逐步上线。`

操作：仅提供“我知道了”。关闭后保持当前页面和输入草稿，不改变路由。

### 17.3 能力异常

1. 能力来源不可用：标记“不可用”，禁止本次选择。
2. 配置缺失：标记“未配置”，详情说明来源。
3. 启停写入失败：回滚开关视觉状态并显示错误。
4. 高级管理器不存在：显示安装或启用提示。

### 17.4 自动化异常

1. 存储不可写：禁止创建/编辑并保留表单输入。
2. 工作空间不存在：运行失败，不自动切换到其他目录。
3. 能力被卸载：运行失败或在开始前标记不可执行，不静默替换。
4. 进程异常退出：重启后按幂等和补跑规则恢复。
5. 等待审批：持续保持状态，除非用户批准、拒绝或取消运行。
6. 同一自动化重叠：后触发运行记为 `skipped`。

### 17.5 插槽兼容失败

插件启动时执行最低兼容检查。如果 Root/Sidebar 或关键官方子插槽不满足契约：

1. 不注册自定义 Root，避免白屏。
2. 保留官方 DSH 界面。
3. 输出结构化诊断日志。
4. 在可用的官方设置/插件区域显示兼容错误。
5. 禁止自动化调度器进入运行状态，避免用户无法查看审批。

## 19. 测试与验收标准

### 19.1 单元测试

1. ScheduleRule 校验与下次运行时间计算。
2. 工作日、指定星期、月度缺失日期和跨时区边界。
3. 重启补跑规则。
4. 幂等键和不重叠策略。
5. Work/Chat 能力解析与 Chat 白名单。
6. 会话迁移的幂等性。
7. 数据 schema 迁移和写入失败回滚。

### 19.2 集成测试

1. 自定义 Root 中官方 Conversation 可创建、发送和恢复会话。
2. Details、Settings、附件和审批组件可正常工作。
3. Work 和 Chat 历史只显示对应模式。
4. 推荐场景和快捷问题只预填、不自动发送。
5. 能力库开关影响默认选择，但不能绕过权限策略。
6. 浏览器关闭后，宿主自动化仍可执行。
7. 插件禁用后官方 DSH 页面恢复。

### 19.3 视觉验收

1. 使用与设计稿一致的视口逐屏截图。
2. 将实现截图与原始设计稿并排比较。
3. 检查品牌资产、字体、字号、行高、边距、圆角、边框、阴影、输入区高度和卡片列宽。
4. Work、Chat 首页分别验收空白、输入、附件、展开配置和窄屏状态。
5. 1024px 验证侧栏折叠与卡片单列。

### 19.4 权限验收

1. Chat 无法获取 Work 工具，即使构造客户端请求也应被宿主拒绝。
2. Work 授权目录内低风险操作可执行。
3. 越界写入、删除、外发和提交必须等待批准。
4. 自动化无人值守时不得自动批准。
5. 拒绝审批后不产生被拒绝的副作用。

### 19.5 数据与回滚验收

1. 迁移前后 DSH 原会话数量、消息和附件一致。
2. 所有旧会话在 Work 中显示“历史导入”。
3. 多次迁移不会重复或覆盖模式元数据。
4. 删除或禁用新插件后，原技能管理器和官方 DSH 仍可运行。
5. 自动化、能力偏好和附加元数据不会污染原会话文件。

## 20. 分阶段开发建议

### 阶段 0：兼容性探针

验证 Root/Sidebar、官方子插槽、宿主服务和存储能力，确定真实依赖版本和最小可行架构。探针失败时先调整接入方案，不进入完整页面开发。

### 阶段 1：品牌壳层与双模式骨架

完成品牌、侧栏、Work/Chat 切换、页面路由、占位弹窗、双草稿和双历史过滤。

### 阶段 2：Work / Chat 核心体验

完成两种首页、输入区、附件、语音转文字、深度思考、联网搜索、推荐场景、快捷内容和模式权限。

### 阶段 3：能力库

完成统一能力模型、搜索筛选、启停、详情和高级管理跳转。

### 阶段 4：自动化

完成持久化调度、创建编辑、运行记录、审批暂停、通知、重启补跑和幂等。

### 阶段 5：迁移、兼容与验收

完成旧会话迁移、异常降级、契约测试、视觉比对、1024px 响应式和插件回滚验证。

## 21. 主要风险与缓解措施

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| DSH 预发布插槽变化 | 壳层无法加载或升级后白屏 | 先做兼容探针；运行时检查；不兼容时回退官方 Root |
| 官方组件依赖原布局上下文 | Conversation/Details 行为异常 | 自定义 Root 重新声明必要插槽并建立契约测试 |
| Chat 仅前端隐藏工具 | 权限绕过 | 在宿主工具注入与执行层实施白名单 |
| 自动化重复触发 | 重复发送、写入或提交 | `automationId + plannedAt` 幂等键；同任务串行 |
| 等待审批阻塞后续周期 | 运行堆积 | 后续触发记为跳过，不并发、不排无限队列 |
| JSON 数据增长 | 加载或写入变慢 | 首期保留运行记录上限/归档策略接口；规模增长后迁移 SQLite |
| 通知权限不可用 | 用户错过结果或审批 | 保存应用内通知，下一次打开后展示 |
| 品牌素材裁切 | UI 与设计稿不一致 | 品牌图形与文字拆分渲染；AI 球使用原图 |

## 22. 实现前仍需验证的技术事实

以下不是待产品决策，而是开发阶段必须通过代码和运行环境确认的事实：

1. 当前目标 DSH 版本中 Root/Sidebar 插槽的精确注册方式。

4. DSH Storage Hub JSON 后端在插件包中的装配方式和数据根目录。
5. Host API Proxy 的公开注册接口。
6. 本机系统通知可复用的 DSH 服务；若无，则实现平台适配器。
7. 浏览器语音转文字在目标浏览器中的能力和权限限制。

这些项目必须在阶段 0 给出可重复的验证记录；若公开 API 与当前推断不一致，应更新实现计划和本设计的技术附录，但不得改变已确认的产品行为。
