# 安装、验证与发布

更新时间：2026-09-02（Asia/Shanghai）

## 安装

当前发布版本：[`@michengai/dsh-skills-manager@0.1.32`](https://www.npmjs.com/package/@michengai/dsh-skills-manager)。推荐直接安装，无需下载源码：

```powershell
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
$OutputEncoding = [System.Text.Encoding]::UTF8
dsh plugin --profile web add @michengai/dsh-skills-manager
```

重启 DSH 后在「设置 → 技能」确认插件界面已更新。若仍显示旧界面，先确认活动 profile 已重新加载该包。若下载镜像尚未同步最新包，可在安装命令末尾添加 `--registry=https://registry.npmjs.org/`。

本地开发或未发布版本可在插件根目录执行 `dsh plugin --profile web add .`。

## 发布新版本

受信发布绑定完成后，维护者只需在插件根目录升级版本并推送版本标签：

```powershell
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
$OutputEncoding = [System.Text.Encoding]::UTF8
npm version patch
npm run pack:check
git push origin master --follow-tags
```

`.github\workflows\publish.yml` 会在推送 `v*` 版本标签时执行，也支持手动触发；它会通过 Corepack 按 `pnpm-lock.yaml` 安装依赖、运行测试，再通过 npm Trusted Publishing（OIDC）发布到官方 npm registry。该方式不需要将 npm 写入令牌保存到 GitHub。

首次启用前，需在 npm 包设置的「Trusted Publisher」中绑定 `MichengAI/dsh-skills-manager` 和工作流文件 `publish.yml`。若自动发布故障，可在完成本机身份验证后执行 `npm publish` 作为人工回退。

包内 `publishConfig.registry` 会强制指向官方 npm registry。发布后，重新执行安装命令即可获取指定版本；回滚时安装已验证版本号，例如 `dsh plugin --profile web add @michengai/dsh-skills-manager@0.1.3`。

## 端到端验收

1. 用户 DSH、公共 Agent 与活动 Git 项目的 DSH/Agent 分组按实际内容显示。
2. 所有用户级与活动项目来源中的有效 Skill 都可逐项启停，且任何开关都不改写来源文件。
3. 设置页可在用户 DSH 或活动项目 DSH 创建新 Skill；上传导入与覆盖仍只作用于用户 DSH。
4. 用户 DSH 与项目 DSH 可移入统一回收站并恢复到原作用域；Agent 来源没有删除入口。
5. 无 `.git`、与用户技能根重叠、或技能根为链接/reparse point 的项目来源不展示且不可写。
6. 按 ESC 时只关闭最上层确认框或上传框。
7. `~\.cc-switch\skills` 作为只读来源默认开启，来源级和逐 Skill 开关只写管理器本地状态。
8. 用户级只读来源中的受控顶层 junction/符号链接可被发现；同一真实 Skill 在 CC Switch、公共 Agent 或应用来源间只展示一次。

### CC Switch 真机证据（2026-09-02）

- 宿主：DSH Web `0.1.2-alpha.3`，临时用户目录、临时 `DSH_HOME`、独立 `web` profile。
- 旧状态：缺少 `ccswitch` 键的 version 1 状态正常迁移，来源默认开启且未触发失败关闭。
- UI：来源级与逐 Skill 停用、恢复、页面重载和显式刷新均生效；浏览器控制台与页面错误为空。
- 链接：公共 Agent junction 指向 CC Switch SSOT 后被识别为只读 Skill；Codex 分发 junction 未造成重复展示。
- 不变性：两份测试 `SKILL.md` 的 SHA-256 在所有开关操作前后保持一致，管理器日志记录为本地策略变更。
- 限制：隔离环境未配置有效工作区 Session，未执行 Session 作用域的官方 `skill.list`；该 Provider 路径由核心测试覆盖。

## 回滚

从 DSH Web profile 移除当前插件或恢复上一个已验证版本，然后重启 DSH。插件不会修改公共 Agent 目录中的文件结构；DSH 根目录内被覆盖或删除的技能需由安装前备份恢复。
