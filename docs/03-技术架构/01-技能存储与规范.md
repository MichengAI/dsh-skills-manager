# 技能存储

更新时间：2026-08-30（Asia/Shanghai）

本文件是插件当前有效的技能存储设计。

## 技能根目录与权限

| 根目录 | 列表 | 启用/停用 | 上传/覆盖 | 删除 |
|---|---|---|---|---|
| `$DSH_HOME\skills` | 支持 | 改写自身调用策略 | 支持 | 移到 manager 回收站 |
| `$DSH_AGENTS_HOME\skills` | 支持并加载 | manager 本地策略 | 不支持 | 不支持 |
| `~/.codex/skills`、`~/.claude/skills`、`~/.gemini/skills`、`~/.config/opencode/skills` | 支持并加载 | manager 本地策略 | 不支持 | 不支持 |
| `<project>/.dsh/skills` | 活动 Session 工作区只读展示 | 不支持 | 不支持 | 不支持 |
| `<project>/.agents/skills` | 活动 Session 工作区只读展示 | 不支持 | 不支持 | 不支持 |

用户级外部 Agent 目录始终只读。其来源级与技能级启停写入 `$DSH_HOME\skills-manager\state.json`，由 manager provider 改变 DSH 的有效调用策略，绝不改写共享的 `SKILL.md`。项目级技能仍由 DSH 官方 filesystem provider 管理；本插件只从活动 Session 的 `header.cwd` 推导最近 `.git` 项目根并提供列表、搜索、诊断与详情，不注册第二个项目 provider，不把项目状态写入用户级 manager 状态文件。

项目来源与 DSH 官方 rank 对齐：`project-dsh` 为 100，`project-agents` 为 200。同一项目内前者覆盖后者；不同项目分别计算同名结果，不把一个 workspace 的赢家标到另一个 workspace 上。此契约核对的上游 revision 为 `deepseek-ai/deepseek-harness@cd5ef8148158c3a752a658978873241fdf8e2bbc`。

## 条目形态

| 形态 | 结构 | 说明 |
|---|---|---|
| bundle | `<root>\<name>\SKILL.md` | 目录型插件，可附带脚本、模板和资源。 |
| flat | `<root>\<name>.md` | 单文件插件。 |

## 管理行为

- 列表读取插件名称、简介、形态与启停状态。
- 项目来源 key 由规范项目根的 SHA-256 摘要生成并携带来源种类；详情请求必须在当前活动 Session 集合中重新解析到同一 key，过期或伪造 key 返回未知来源。客户端不能提交任意 cwd。
- 项目状态与详情按请求重新扫描，因此新增、修改和删除会在刷新后体现；DSH 模型目录的 watcher/invalidation 仍完全由官方 filesystem provider 负责。
- 项目赢家在 UI 中标记为“已发现”，不标记为“已加载”；本插件的宿主扫描不能替代 Session 作用域 catalog，也不把“被发现”误报为模型已看到或已遵循。
- 项目 bundle 若经符号链接或 Windows reparse point 落到该项目 Skill 根外，管理器不跟随也不展示，避免设置页读取项目边界外内容。
- 上传技能文件夹或 ZIP 时保留其完整目录资源；单独上传 `SKILL.md` 时按 frontmatter `name` 创建 bundle 并复制到 `$DSH_HOME\skills`。
- 同名上传以规范化后的技能名判断，bundle 与 flat 两种形态之间也必须确认后才覆盖；覆盖会清理该名称的两种形态，只保留新上传的条目。
- DSH 技能停用写入 `disable-model-invocation: true` 与 `user-invocable: false`；外部技能停用只更新 manager 状态。禁用的外部候选仍由 provider 以双 false 返回，阻止低优先级重名副本意外激活。由于 Agent 预设会在更近的技能作用域挂载 filesystem provider，manager provider 也会为每个存活 Agent 注册同名作用域候选；否则全局层的禁用候选无法覆盖预设层的公共 Agent 技能。
- 启停只替换 DSH 技能中两个调用策略行，其他 frontmatter（含引号、嵌套结构与 `|`/`>-` 块文本）按原样保留。启用删除这两行以恢复缺省可调用，不还原这两行的原始文本或行内注释。
- frontmatter 读取只解析顶层 `key: value`；嵌套字段不进入状态快照。若以后要读取 `metadata.*`，必须更换解析器。
- 每次成功写入 DSH 技能后立即使 DSH 技能目录缓存失效，并通知 Web `/` 菜单重拉候选；官方 `skills/change` 目前不会转发到浏览器，因此借用已转发的 `agent-preset/selected`（仅发送该会话当前预设，不改写预设）。
- 删除只接受 DSH 列表中的同名条目，并移动到 `$DSH_HOME\skills-manager\trash`；恢复遇到同名技能时拒绝，永久删除为二次操作。Windows 下目录改名仅针对 `EACCES`、`EBUSY`、`EPERM` 做有上限的短退避重试；最终 stage 发布仍被占用时降级为逐项复制，并最后写入 `metadata.json`，因此回收站列表不会暴露半成品且 stage 始终可用于回滚。其他错误立即透传。
- 详情接口返回正文、frontmatter、路径与诊断；诊断覆盖缺失/非法名称、缺少简介、调用策略非法与重名遮蔽，不自动改写源文件。
- 设置页和 `create_skill` 对话工具都只在 `$DSH_HOME\skills` 创建 bundle，拒绝覆盖；对话工具通过 `tools/pre-execute` 请求审批。
- 单条导入全部失败时，接口返回错误；批量导入部分失败时，保留成功条目并返回每项失败原因。
