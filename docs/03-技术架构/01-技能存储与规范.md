# 技能存储

更新时间：2026-09-01 23:53（Asia/Shanghai）

本文件是插件当前有效的技能存储设计。

## 技能根目录与权限

| 根目录 | 列表 | 启用/停用 | 上传/覆盖 | 删除 |
|---|---|---|---|---|
| `$DSH_HOME\skills` | 支持 | manager 本地逐 Skill 策略 | 支持 | 移到 manager 回收站 |
| `$DSH_AGENTS_HOME\skills` | 支持并加载 | manager 本地策略 | 不支持 | 不支持 |
| `~\.cc-switch\skills` | 支持并加载，来源默认开启 | manager 本地策略 | 不支持 | 不支持 |
| `~/.codex/skills`、`~/.claude/skills`、`~/.gemini/skills`、`~/.config/opencode/skills` | 支持并加载 | manager 本地策略 | 不支持 | 不支持 |
| `<project>/.dsh/skills` | 活动 Session 工作区展示 | manager 本地逐 Skill 策略 | 仅支持创建新 bundle，不支持上传/覆盖 | 移到 manager 回收站并恢复到原项目 |
| `<project>/.agents/skills` | 活动 Session 工作区展示 | manager 本地逐 Skill 策略 | 不支持 | 不支持 |

所有来源的逐 Skill 启停都写入 `$DSH_HOME\skills-manager\state.json`，由 manager provider 改变 DSH 的有效调用策略，绝不改写来源 `SKILL.md` 或单文件 Skill。状态使用 `enabledSkills`、`disabledSkills` 与无覆盖三态；显式用户 DSH 策略通过 rank 399 候选执行，显式项目 DSH/Agent 策略仅为相同 cwd 提供 rank 99/199 候选。无覆盖时仍由 DSH 官方 filesystem provider 管理。项目 DSH 仅在用户显式创建、移入回收站或恢复时写入文件；项目 Agent 始终不可删除。

项目来源与 DSH 官方 rank 对齐：`project-dsh` 为 100，`project-agents` 为 200。同一项目内前者覆盖后者；不同项目分别计算同名结果，不把一个 workspace 的赢家标到另一个 workspace 上。此契约核对的上游 revision 为 `deepseek-ai/deepseek-harness@cd5ef8148158c3a752a658978873241fdf8e2bbc`。

用户级来源依次使用 DSH 400、公共 Agent 450、CC Switch 510、Codex 520、Claude 530、Gemini 540、OpenCode 550。CC Switch 使用固定 `~\.cc-switch\skills` SSOT；当同一真实技能被链接到其他 Agent 根时，状态与 Provider 按 realpath 只保留 rank 更高的一份。旧版状态缺少 `ccswitch` 键时只补齐 `sources.ccswitch=true` 与空策略列表，其他结构损坏仍失败关闭。

## 条目形态

| 形态 | 结构 | 说明 |
|---|---|---|
| bundle | `<root>\<name>\SKILL.md` | 目录型插件，可附带脚本、模板和资源。 |
| flat | `<root>\<name>.md` | 单文件插件。 |

## 管理行为

- 列表读取插件名称、简介、形态与启停状态。
- 项目来源必须能从活动 Session cwd 找到真实 `.git` 祖先，不把无 Git 工作区回落为项目。来源 key 由规范项目根的 SHA-256 摘要生成并携带来源种类；详情和写请求必须在当前活动 Session 集合中重新解析到同一 key，过期或伪造 key 返回未知来源。客户端不能提交任意 cwd。
- 项目状态与详情按请求重新扫描，因此新增、修改和删除会在刷新后体现；DSH 模型目录的 watcher/invalidation 仍完全由官方 filesystem provider 负责。
- UI 与状态快照统一使用“已启用/已停用”描述调用策略，不再使用“已加载/已发现”。本插件的宿主扫描不能证明正文已进入 Session；完整 Skill 正文仍由 DSH 在实际调用时按需读取。
- 项目来源若与任一用户技能根重叠，或 `.dsh`/`.agents` 容器、技能根、bundle 经符号链接或 Windows reparse point 重定向，管理器不跟随、不展示并拒绝写入，避免跨越权限域。
- 用户级只读来源可跟随顶层 bundle 链接，但目标必须是另一个已知只读 Skills 根中符合普通名称规则的直接子目录，`SKILL.md` 必须为普通文件；候选加载时再次比较真实 bundle 与文档路径。可写 DSH 根、项目根、链接形式的 Skills 根、隐藏或非法目标及任意根外目标继续拒绝。
- 上传技能文件夹或 ZIP 时保留其完整目录资源；单独上传 `SKILL.md` 时按 frontmatter `name` 创建 bundle 并复制到 `$DSH_HOME\skills`。
- 同名上传以规范化后的技能名判断，bundle 与 flat 两种形态之间也必须确认后才覆盖；覆盖会清理该名称的两种形态，只保留新上传的条目。
- 所有来源的逐 Skill 启停只更新 manager 三态策略，不改写来源文件。禁用的外部候选仍由 provider 以双 false 返回，阻止低优先级重名副本意外激活。由于 Agent 预设会在更近的技能作用域挂载 filesystem provider，manager provider 也会为每个存活 Agent 注册同名作用域候选；否则全局层的禁用候选无法覆盖预设层的公共 Agent 技能。
- frontmatter 读取只解析顶层 `key: value`；嵌套字段不进入状态快照。若以后要读取 `metadata.*`，必须更换解析器。
- 每次成功写入 DSH 技能后立即使 DSH 技能目录缓存失效，并通知 Web `/` 菜单重拉候选；官方 `skills/change` 目前不会转发到浏览器，因此借用已转发的 `agent-preset/selected`（仅发送该会话当前预设，不改写预设）。
- 删除只接受用户 DSH 或活动项目 DSH 列表中的同名条目，并移动到 `$DSH_HOME\skills-manager\trash`；metadata 保存原作用域，项目恢复时重新校验活动项目身份、目录安全和同名冲突。永久删除为二次操作。跨盘移动复制完整内容后隐藏源路径；Windows 下目录改名仅针对 `EACCES`、`EBUSY`、`EPERM` 做有上限的短退避重试，最终 stage 发布仍被占用时降级为逐项复制并最后写入 `metadata.json`。
- 详情接口返回正文、frontmatter、路径与诊断；诊断覆盖缺失/非法名称、缺少简介、调用策略非法与重名遮蔽，不自动改写源文件。
- 设置页可在 `$DSH_HOME\skills` 或活动项目 `<project>/.dsh/skills` 创建 bundle，拒绝覆盖；`create_skill` 对话工具仍只写 `$DSH_HOME\skills`，并通过 `tools/pre-execute` 请求审批。
- 单条导入全部失败时，接口返回错误；批量导入部分失败时，保留成功条目并返回每项失败原因。
