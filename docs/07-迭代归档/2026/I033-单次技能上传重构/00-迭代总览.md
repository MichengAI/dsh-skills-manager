# I033 单次技能上传重构

## 目标

将原先“选择 SKILL.md → 取不到绝对路径 → 再打开内置目录浏览器”的链式流程，重构为与豆包、千问一致的单弹窗上传体验。

## 已完成

- 一个上传区域统一接收 `.zip`、技能文件夹和单个 `SKILL.md`。
- 文件与文件夹均使用浏览器原生选择能力；不会再自动弹出第二个选择器。
- 支持拖放普通文件与递归读取拖放文件夹。
- 客户端只上传文件内容和相对路径，不读取或提交本机绝对路径。
- 新增 `POST /upload`，使用管理器私有暂存目录并复用既有原子导入、冲突和刷新链路。
- ZIP 使用直接依赖 `fflate@0.8.3` 解压；限制请求体、压缩包、单文件、总展开大小、条目数、路径长度和深度。
- 拒绝绝对路径、路径穿越、Windows 设备名、重复路径与非法 Base64；归档内容始终写成普通文件。
- 补充核心、HTTP、双语词典和客户端契约回归。
- 上传区的文件/文件夹选择改用中性文字色；绿色仅保留给成功等语义状态。
- Windows 最终发布回收站 stage 遇到持续 `EPERM` 时，降级为“逐项复制、最后写 metadata”，避免短重试耗尽后误回滚。

## 验证

- `npm test`：249 项核心测试、894 项本地化/客户端契约测试通过。
- 本地 DSH Web `http://127.0.0.1:3080/`：选择单个 `SKILL.md` 后显示文件摘要，点击安装成功导入并刷新技能目录；临时测试技能已清理。
- 本地真实条目 `byteplus-seedance` 已成功移入回收站，并在状态快照与回收站弹窗中可见。
- 视觉对照：同时比较千问、豆包参考与 DSH 实装；信息结构、上传区、文件要求和主操作层级一致，颜色、圆角与按钮沿用 DSH 设计令牌。
