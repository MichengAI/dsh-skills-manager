## 目标与业务边界

处理 npm 下载镜像导致的发布拒绝问题：发布时强制使用官方 npm registry，安装时仍允许使用镜像加速，无需下载源码。

## 任务清单

- [x] 检查当前 npm registry，确认其为 `https://registry.npmmirror.com`。
- [x] 将 `publishConfig.registry` 固定为 `https://registry.npmjs.org/`。
- [x] 保留公开发布权限配置，并补充官方 registry 登录步骤。
- [x] 补充镜像同步滞后的官方 registry 安装后备命令。
- [x] 更新安装、发布与回滚命令。

## 验收标准

- [x] `package.json` 发布配置明确指向官方 npm registry。
- [x] 安装说明兼容下载镜像与官方 registry 后备。
- [x] 包的实际运行时代码与资源仍包含在 tarball 中。
- [x] `npm publish --dry-run` 明确显示发布目标为 `https://registry.npmjs.org/`。

## 已完成内容

`registry.npmmirror.com` 是下载镜像而非发布 registry，因此产生 “Public registration is not allowed”。`npm publish` 读取包内配置后会改用官方 npm registry；使用者仍可直接执行 `dsh plugin --profile web add dsh-skills-manager`。

## 待处理事项

维护者在官方 npm registry 完成登录后执行 `npm run pack:check` 与 `npm publish`，并在真实 DSH Web profile 中验证按包名安装。
