# I034-反向代理Host信任修复 · 迭代总览

- 状态：已完成
- 日期：2026-08-28
- 关联问题：GitHub Issue #3
- 发布版本：`v0.1.30`

## 目标与业务边界

修复 Skills Manager 在 DSH Web 已通过 `--trusted-host` 信任的反向代理域名或 LAN 地址下，全部 HTTP 接口仍因插件自身 loopback-only 校验返回 403 的问题。默认 loopback 行为与未知 Host 拒绝策略不放宽，Host 信任仍不替代认证。

## 任务清单

- [x] 从 `webRuntime.trustedHosts` 继承 DSH Web 已解析的 LAN IP 与显式 authority。
- [x] 对 Host 和信任条目执行规范 authority 校验，带端口条目精确匹配、不带端口条目匹配任意端口。
- [x] 拒绝未知 Host、异源 `Origin` 与显式 `sec-fetch-site: cross-site` 请求。
- [x] 保留写接口的 JSON 与 `x-dsh-skills-manager: 1` 二次约束。
- [x] 更新中英文 README、HTTP 接口文档和技术架构基线。

## 验收标准

- [x] loopback、DSH 显式受信域名和派生 LAN IP 均可访问 GET 与 POST 接口。
- [x] 未声明域名、错误端口、非规范条目、异源 Origin 与 cross-site 请求均返回 403。
- [x] 受信 Host 不绕过写接口客户端标记。
- [x] `node test/core-test.mjs`：272 项通过。
- [x] `node test/locale-test.mjs`：903 项通过。

## 已完成内容

插件不再维护与 DSH Web 冲突的 loopback-only 信任边界，而是将 `webRuntime` 声明为 host 端依赖，复用宿主 runtime 已决定的 authority，并在自身 REST 路由上保持等价的 DNS rebinding 与跨站防护。
