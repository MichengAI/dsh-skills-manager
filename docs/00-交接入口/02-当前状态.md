# 当前状态

更新时间：2026-09-03 11:23（Asia/Shanghai）

## 当前阶段

`0.1.32` 把所有来源的逐 Skill 启停统一为 manager 本地三态策略：用户 DSH、外部 Agent、项目 DSH 与项目 Agent 的来源文件均保持不变。项目 `.dsh/skills` 继续支持设置页创建、移入统一回收站并恢复到原项目；这些显式文件操作不属于启停。

界面与状态快照已将“已加载/已发现”统一为“已启用/已停用”，只描述调用策略，不再暗示完整 Skill 正文已经进入 Session。没有显式覆盖时，项目 Skill 的 catalog 与正文加载仍由 DSH 官方 filesystem provider 负责；显式覆盖由 manager 的 workspace 策略候选执行。

项目写入边界已加固：无 `.git` 的 cwd 不再回落为项目根；与任一用户技能根重叠或通过符号链接/reparse point 重定向的项目来源不会展示，也不能写入。技能根本身的链接不会被列表或详情跟随。

`0.1.34` 发布 CC Switch 后续加固：默认开启的只读来源继续固定读取 `~\.cc-switch\skills`；用户级只读根可识别指向其他已知只读 Skills 根直接子目录的顶层 bundle 链接，并按真实路径去重。旧状态缺少 CC Switch 键时兼容补齐，其他损坏状态仍失败关闭。

未发布加固将同一真实 Skill 的归属调整为直接 SSOT 优先：公共 Agent 或应用目录中的分发链接不再抢占 CC Switch 直接条目，规范候选仍继承所有入口中的最强 rank。Provider 对用户级和项目级候选都要求并复验真实 bundle 与文档路径，用户根并发扫描且只在单次请求内复用受信根解析结果。

当前分发条目从某个来源迁移到规范 SSOT 时，来源自身无显式策略的前提下，原分发来源的逐 Skill 停用会继续生效；规范来源自身的显式启停优先。详情接口按被请求条目的物理所有者复现状态快照的用户根去重结果，不再读取无关 Skill 文档；文件系统竞态统一失败关闭。

运行源码现统一维护在 `src\`，`lib\` 仅保存 `esbuild` 生成的 Host、AMD 客户端和 source map 发布物。测试先构建再验证实际发布产物，发布流程额外检查 `lib\` 与 `src\` 是否同步。
