# 当前状态

更新时间：2026-08-31（Asia/Shanghai）

## 当前阶段

`0.1.32` 把所有来源的逐 Skill 启停统一为 manager 本地三态策略：用户 DSH、外部 Agent、项目 DSH 与项目 Agent 的来源文件均保持不变。项目 `.dsh/skills` 继续支持设置页创建、移入统一回收站并恢复到原项目；这些显式文件操作不属于启停。

界面与状态快照已将“已加载/已发现”统一为“已启用/已停用”，只描述调用策略，不再暗示完整 Skill 正文已经进入 Session。没有显式覆盖时，项目 Skill 的 catalog 与正文加载仍由 DSH 官方 filesystem provider 负责；显式覆盖由 manager 的 workspace 策略候选执行。

项目写入边界已加固：无 `.git` 的 cwd 不再回落为项目根；与任一用户技能根重叠或通过符号链接/reparse point 重定向的项目来源不会展示，也不能写入。技能根本身的链接不会被列表或详情跟随。

## 活动迭代

全来源非破坏性启停、状态语义与 i18n 契约修正已经完成；待完成真机验证、完整代码审查与发布闭环。

## 有效风险

- 斜杠菜单刷新仍借用宿主已转发的 `agent-preset/selected`；后续若 DSH 正式转发 `skills/change`，应切换为官方事件。
- 浏览器自动化端到端回归尚未纳入持续集成，当前依赖核心测试、本地化契约测试与本机 DSH Web 冒烟。
- `core.js` 仍集中承载多类核心职责；属于后续可维护性改进，不影响本次缺陷修复。
- 项目 DSH 当前支持表单新建，但上传导入与覆盖仍只作用于 `$DSH_HOME\skills`。
