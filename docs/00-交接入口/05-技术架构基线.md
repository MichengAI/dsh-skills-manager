# 技术架构基线

更新时间：2026-08-30（Asia/Shanghai）

## 生效的技术硬约束

- 插件形态：标准 DSH Web 插件（`package.json` 元数据 + `exports["./client"]` AMD bundle + `cordis.patch.yml`）。
- 语言：纯 JavaScript（ESM），零构建步骤，不引入 TypeScript 编译链。
- host 半区除 ZIP 解压使用 `fflate@0.8.3` 外，仅使用 `node:` 内置模块与 cordis 服务注入。
- 客户端仅 `require("react")`，通过 `window.__ModuleLoader__` AMD 装载，注册 ID 必须与 `package.json.name` 完全一致；React 由宿主提供，禁止内联第二份实例。
- 数据源：活动 Session 项目根下的 `.dsh/skills`、`.agents/skills`，以及 `$DSH_HOME\skills`、`$DSH_AGENTS_HOME\skills`、Codex、Claude、Gemini 与 OpenCode 用户级 Skills 根。
- 项目作用域：只信任 `sessions.list()` 返回的 `header.cwd`，必须找到最近的真实 `.git` 根，不对普通目录回落；动态来源 key 绑定规范项目根与来源种类。项目级 `.dsh`/`.agents` rank 分别为 100/200，按 workspace 独立判定，不注册重复 provider、不写 manager 状态。与任一用户技能根重叠，或容器/技能根为符号链接或 reparse point 的项目来源直接隐藏并拒绝写入。
- 加载优先级：DSH 本地保持官方 rank 400；manager provider 以 Agents 450、Codex 520、Claude 530、Gemini 540、OpenCode 550 提供只读候选，保证本地 DSH 优先。provider 同时注册在宿主全局层和每个存活 Agent 的作用域层；后者用于覆盖 Agent 预设自带的 filesystem provider，避免已停用技能从更近的预设层重新出现。
- 启用/停用/删除：用户 DSH 与活动项目 DSH 根会改写或移动自身文件；用户级外部来源启停写入 `$DSH_HOME\skills-manager\state.json`，项目 Agent 来源只读。解析根与条目均使用 lstat，根链接不跟随，条目 realpath 必须仍在技能根内。
- 写入后：通过 `skills` 服务使目录缓存失效；并补发 `commands/change` 与带当前预设的 `agent-preset/selected`，让 Web `/` 菜单立刻重拉 `skills.list`。官方 `skills/change` 尚未转发到浏览器。
- 创建、导入和删除：设置页可在 `$DSH_HOME\skills` 或活动项目 `<project>/.dsh/skills` 创建 bundle，均拒绝覆盖；`create_skill` 对话工具和上传导入仍只写用户 DSH。用户与项目 DSH 删除都进入 manager 统一回收站，metadata 保留原作用域，恢复项目条目时要求原项目仍处于活动 Session。Windows 跨盘移动使用复制后隐藏源路径，瞬时目录占用先重试 `EACCES`、`EBUSY`、`EPERM`，最终 stage 发布失败时复制并最后发布 metadata。
- 弹窗：共享 `Modal` 在处理 `Escape` 时同时执行 `preventDefault`、`stopPropagation` 与原生 `stopImmediatePropagation`，每次只关闭当前最上层确认框或上传框，不把按键继续传给设置页。
- 导入选择：一个上传弹窗使用浏览器原生文件/文件夹选择器和拖放，统一接收 `.zip`、技能文件夹或单个 `SKILL.md`。客户端读取内容与相对路径后调用 `/upload`，不依赖 `File.path`，也不串联第二个目录浏览器。
- 提供正文详情、frontmatter 与诊断；不自动修复外部源文件。
- 路由：host 挂载 `webServer` 前缀路由 `/api/dsh-skills-manager`。全部接口（含 GET `/state`）允许 loopback 或 `webRuntime.trustedHosts` 中的规范 authority；POST 接口要求 `application/json` 及 `x-dsh-skills-manager: 1`。
- 信任边界：插件继承 DSH Web 从 LAN 绑定和 `--trusted-host` 得出的信任列表，带端口条目精确匹配、不带端口条目匹配任意端口；未知 Host、异源 Origin 与显式 cross-site 请求失败关闭。该栅栏只防 DNS rebinding，不是认证。`/upload` 只接受 Base64 内容与受限相对路径，在 `$DSH_HOME/skills-manager/uploads` 暂存并校验路径穿越、数量、单文件和总大小后复用原子导入链路。
- 插槽：客户端注册 `settings.section`，`id: skills-manager`，`order: 17`。
- 调用状态：无法识别的 `disable-model-invocation` 或 `user-invocable` 值显示为“配置异常”，仅 DSH 本地技能可通过“修复并启用”恢复默认调用状态。
- 国际化：UI 文案全部经 `locale` 服务的双语词典（zh/en）翻译；`settings.section` 注册声明 `locale` 命名空间，`label` 用 thunk 跟随语言切换。host 业务错误返回 `{ error, code, params }`，client 是唯一翻译点；协议错误带 `error.proto.*` 码，非法 Host 与缺少写请求标记分码。导入回滚失败和备份未清理也带可翻译码，不把 Node 系统码抄到业务 `code` 上。

## 关键服务依赖

| 平台 | 服务/注入 | 用途 |
|---|---|---|
| host | `webServer`、`webRuntime`、`skills`、`tools`、`sessions` | 注册 HTTP 路由、继承 DSH Web 信任 authority、注册外部 provider 与对话创建工具、从活动 Session 推导项目根，并刷新技能目录与 Web `/` 菜单 |
| client | `slots`、`locale` | 注册设置分区；双语词典与翻译（`locale: NS` 注入 t seat） |
| client（构建期） | `@deepseek-ai/dsh-client-runtime`、`@deepseek-ai/dsh-client-ui-slots`、`@deepseek-ai/dsh-client-locale` | `package.json` 的 `dsh.client.inject` 声明 |
